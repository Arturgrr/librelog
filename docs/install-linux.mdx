title: "Install on Linux"
description: "Install Librelog on Fedora, Ubuntu or any x86_64 distribution, and learn how updates work there."
---

Every release on [GitHub Releases](https://github.com/Arturgrr/librelog/releases/latest) has three Linux packages for x86_64 computers. ARM64 has no packages; [build from source](/desktop-installation#build-from-source) there.

| Package | For | Updates |
| --- | --- | --- |
| `Librelog-<version>-1.x86_64.rpm` | Fedora | Download the new package from the release page |
| `Librelog_<version>_amd64.deb` | Ubuntu 24.04 or later, Debian | Download the new package from the release page |
| `Librelog_<version>_amd64.AppImage` | Other distributions | From inside the app |

<Note>
  Librelog on Linux is a beta. Expect rough edges, and report problems from **Help → Report Bug** with your distribution, desktop and Librelog version.
</Note>

## What you need

- An x86_64 computer with a distribution at least as new as Ubuntu 24.04 (glibc 2.39). The packages are built on Ubuntu 24.04.
- Fedora 42 or later is recommended on GNOME: it has the desktop portal Librelog uses for global keyboard shortcuts.
- On KDE Plasma, Plasma 6 with `xdg-desktop-portal-kde`, which Plasma installs. See [KDE Plasma](#kde-plasma).
- On GNOME, the [AppIndicator extension](https://extensions.gnome.org/extension/615/appindicator-support/) to see the Librelog icon in the top bar. On Fedora, install it with `sudo dnf install gnome-shell-extension-appindicator`, log out and back in, and turn it on in the Extensions app. Without it, Librelog runs without a top-bar icon, closing its window minimizes it instead of hiding it, and you quit it from **File → Quit Librelog** in its title bar or with Control + Q.
- A Vulkan-capable GPU is optional. Local models use it when it works and transcribe on the CPU otherwise. The RPM and deb install the Vulkan loader, and the AppImage carries one.

On Wayland sessions Librelog's windows run through XWayland for now, so the dictation indicator and the meeting bar can stay where they belong and above other windows; shortcuts and pasting still go through your desktop's Wayland portals. With fractional scaling (125% or 150%), XWayland windows can look blurry. To run Librelog natively on Wayland instead, start it with `LIBRELOG_WAYLAND=1 librelog` (or put the variable before the AppImage): windows are sharp, but GNOME then decides where the dictation indicator, the meeting bar and notifications appear and may put other windows above them.

## Fedora

1. Download the `.rpm` file from the [latest release](https://github.com/Arturgrr/librelog/releases/latest).
2. In the folder that holds it, run:

   ```bash
   sudo dnf install ./Librelog-*.x86_64.rpm
   ```

   dnf installs the libraries Librelog needs from Fedora's repositories: WebKitGTK, GTK, PipeWire, the PulseAudio and ALSA client libraries, the GStreamer plugins, the Vulkan loader and the AppIndicator library.
3. Open Librelog from the app grid and follow the setup screen.

The RPM is not signed with a GPG key. Check it against the release's checksums before you install it (see [Verify the download](#verify-the-download)).

To remove Librelog, run `sudo dnf remove librelog`.

## Ubuntu and Debian

1. Download the `.deb` file from the [latest release](https://github.com/Arturgrr/librelog/releases/latest).
2. In the folder that holds it, run:

   ```bash
   sudo apt install ./Librelog_*_amd64.deb
   ```

3. Open Librelog from the app grid.

To remove Librelog, run `sudo apt remove librelog`.

## AppImage

1. Download the `.AppImage` file from the [latest release](https://github.com/Arturgrr/librelog/releases/latest).
2. Make it executable and run it:

   ```bash
   chmod +x Librelog_*_amd64.AppImage
   ./Librelog_*_amd64.AppImage
   ```

The AppImage uses your system's PipeWire and Wayland libraries rather than copies from Ubuntu, which would not find PipeWire's modules on Fedora. GNOME and KDE desktops have them; on a minimal system, install PipeWire's libraries and the four Wayland ones (`libwayland-client`, `libwayland-cursor`, `libwayland-egl` and `libwayland-server`). If it does not start because FUSE is missing, run it with `--appimage-extract-and-run`. The first time it runs, the AppImage adds a Librelog launcher to your app grid, `~/.local/share/applications/com.arturgrr.librelog.desktop`: your desktop needs it to know Librelog for global shortcuts and the paste permission. Librelog points it at the AppImage again whenever the AppImage moves, and removes it if you later install the RPM or deb, which bring their own.

## Updates

Librelog checks GitHub Releases for new versions on every package type. What happens next depends on how you installed it:

- **AppImage**: Librelog downloads and installs the new version in place, then restarts, as it does on macOS. **Settings → General → Automatically install updates** controls whether it does this on its own.
- **RPM and deb**: the system package manager owns these installs, so Librelog does not replace itself. It shows that a new version is available, and **Download** opens that version's release page. Install the new package the same way as the first one: `sudo dnf install ./Librelog-*.x86_64.rpm` or `sudo apt install ./Librelog_*_amd64.deb` upgrades the installed version.

## Verify the download

Every release lists SHA-256 checksums in `SHA256SUMS.txt`. Download it next to the package, then run in that folder:

```bash
sha256sum -c SHA256SUMS.txt --ignore-missing
```

## What works differently on Linux

- **Shortcuts.** On Wayland your desktop asks you to approve Librelog's shortcuts and may let you choose other keys. See [Dictation](/dictation#linux).
- **Dictation.** Text goes into the focused field through accessibility, or is pasted through the clipboard where a field does not take it. On Wayland your desktop asks once to let Librelog press the paste keys.
- **Screenshots and recordings.** They use your desktop's screenshot tool and screen-sharing dialog. Recordings are MP4, or WebM when no H.264 encoder is installed, and have no sound, countdown or outline yet. On Fedora, `gstreamer1-plugin-openh264` provides the H.264 encoder; dnf installs it with the RPM when the Cisco OpenH264 repository is enabled. See [Screenshots and recordings](/capture#on-linux).
- **Annotate.** The capsule and your red marks are part of the screen recording. With `LIBRELOG_WAYLAND=1` there is no drawing overlay. See [Annotate](/annotate#on-linux).
- **Built-in models.** The model server ships inside the packages and needs a CPU with AVX2. It uses your GPU through Vulkan when it works.

## KDE Plasma

Librelog runs on Plasma 6 on Wayland (Fedora KDE, Kubuntu, KDE neon, Arch and others) through KDE's desktop portals. Plasma 5 is not tested.

What works as on GNOME, without extensions:

- **The tray icon.** Plasma shows it in the system tray, and closing Librelog's window hides it there. The icon is dark on a light panel and white on a dark one, following Plasma's colour scheme; with a third-party Plasma style it gets a dark outline that shows on either. Librelog's notifications also follow the colour scheme.
- **Shortcuts.** Librelog's shortcuts go through KDE's Global Shortcuts portal. KDE may ask you to confirm them the first time; afterwards they are listed under **Librelog** in **System Settings → Keyboard → Shortcuts**, where you can give them other keys, and Librelog's Settings show the keys KDE uses. KDE reports when you let go of a shortcut, so holding the dictation shortcut to talk works. Control + Alt + period cancels a dictation; Control + Alt + Escape stays KWin's.
- **Pasting.** The first dictation that needs a paste makes KDE ask whether Librelog may control the keyboard (remote control). If KDE gives Librelog a way to restore that approval, Librelog keeps it and does not ask again. On Plasma versions that do not, KDE asks again each time Librelog starts, and Plasma may show that the computer is being controlled remotely for as long as Librelog runs.
- **Screenshots, recordings and Annotate.** They use KDE's screenshot and screen-sharing dialogs.
- **The Trash.** Deleting a capture moves it to the Trash, which Dolphin lists, with or without GNOME's `gio`.

### Accessibility for Qt apps

Dictation types into native fields through accessibility (AT-SPI). Plasma leaves it off for Qt and KDE apps, so to Librelog they show no field: dictation pastes into them instead, cannot leave out their password fields, and cannot tell which app is in front. To turn accessibility on for Qt apps, create `~/.config/plasma-workspace/env/qt-accessibility.sh` with this line, then log out and back in:

```bash
export QT_LINUX_ACCESSIBILITY_ALWAYS_ON=1
```

Turning on the screen reader in **System Settings → Accessibility** also works, but turns accessibility on for every app, which can slow some of them down.

### Konsole and Yakuake

Without accessibility (above), Librelog cannot tell that Konsole or Yakuake is in front, so it presses Control + V, which they do not paste: in bash it inserts the next key literally. Turn on accessibility for Qt apps, or copy the dictation from **Settings → Dictation history** and paste it with Control + Shift + V.

### Scaling

Librelog's windows run through XWayland. With fractional scaling (125% or 150%), the **Legacy applications (X11)** setting in **System Settings → Display & Monitor** decides how they look: **Scaled by the system** makes them blurry, **Apply scaling themselves** keeps them sharp but they may look smaller than other apps. Starting Librelog with `LIBRELOG_WAYLAND=1` makes it sharp at the right size, but KWin then places the dictation indicator, the meeting bar and notifications itself and may cover them, and Annotate has no ink.

### Known limitations on KDE

- Without accessibility for Qt apps, a dictation's history entry and Annotate's summary have no app name, and **Send after pasting** never presses Return.
- The dictation indicator, the meeting bar and notifications stay below full-screen windows.
- Annotate stops drawing 8 seconds after you press its shortcut, as on other Wayland desktops, even though KDE reports the release.
- Plasma 5 and xdg-desktop-portal versions before 1.19 (Kubuntu 24.04) are not tested. With them, a Librelog started at login or from a terminal can count as another app, so KDE asks for its shortcuts and remote control again.

## What is not available on Linux yet

- App Lock
- Apple-only transcription models: Soniqo and Apple Speech
- Apple Reminders and Contacts
- The notch indicator and the Dock icon setting
- Replacing the system's own screenshot shortcuts
- Packages for ARM64

</Warning>
